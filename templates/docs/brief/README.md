# Brief docs: index

The main product brief and one short brief per feature. Read one only when the task touches it. Add one line here when you add a doc. Archive a feature brief with `git mv` once the feature is live and nothing refers to it.

## Current state
- `product-brief.md`: the main product brief (who it is for, the problem, overall scope).
- `features/`: one midweight brief per new feature (what, why, success, scope, steps, open questions).
